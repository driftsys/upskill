# AD-0047 — Plugin-first setup

Status: **accepted**. Date: 2026-11-26. Amends
[AD-0044](0044-plugin-output-of-a-bundle.md). The design is
[the plugin-first setup design](../archive/specs/2026-11-25-plugin-first-setup-design.md).

## Context

Setting up upskill took three unconnected steps: run `install.sh`, add the
marketplace and install the notice plugin for each client, and run
`upskill add driftsys/upskill`. The notice plugin in `driftsys/metapowers` was a
hand-copied copy of `plugins/`. Users also read the skill name `upskill-cli` as
the name of a second program.

## Decision

1. **One plugin.** The plugin `upskill@metapowers` is the setup path for Claude
   Code and Copilot CLI. It gives the upskill skills, a session-start hook that
   prints the install command when the `upskill` CLI is missing, the update
   notice for installed content, and a notice for a newer CLI release.
2. **Generated by `pack`.** The plugin is the output of `upskill pack upskill`
   from `skills/upskill.bundle.yaml`. The bundle `prompt-engineering` is renamed
   `upskill`, because `pack` names the plugin after the bundle. The standalone
   notice plugin of `plugins/` is no longer published. `pack` still embeds its
   hook files in the plugin of every bundle that has rules.
3. **Setup hook.** A command hook item, `skills/upskill-setup/`, runs on
   `session-start`. When `upskill` is not on `PATH`, it prints the install
   command at most once a day. Otherwise it runs `upskill update --notice`
   (`--repeat` for Copilot CLI). It installs nothing and exits 0 in every case.
4. **Release check in the CLI.** `upskill update --notice` also checks for a
   newer CLI release. It lists the tags `vMAJOR.MINOR.PATCH` of
   `driftsys/upskill` with `git ls-remote --tags`, at most once in 24 hours,
   with a 3-second limit. It prints one line with the `install.sh` command once
   for each latest version, or at every run with `--repeat`.
   `UPSKILL_NO_UPDATE_CHECK` set to a nonempty value skips the check. A failure
   prints nothing, and the next attempt waits for the 24 hours. `update --check`
   does not include it.
5. **Skill rename.** The skill `upskill-cli` is renamed
   `upskill-managing-content`. No alias and no migration exist (pre-1.0).
6. **Installer.** `install.sh` prints on stderr, after the version line, the
   commands that install the plugin for each client, and the `upskill add`
   command for opencode. It runs nothing.
7. **Publishing.** The release step in `CONTRIBUTING.md` checks out the release
   tag and runs `pack` into a checkout of `driftsys/metapowers` with `--force`.
   The step is manual.
8. **Existing installs.** A user who installed the skills with
   `upskill add driftsys/upskill` gets each skill twice. The documentation tells
   the user to run `upskill remove` on those skills, with `--global` for a
   global install, before the next `upskill update`. No code or `doctor` check
   handles it.

## Amendments to AD-0044

- The standalone notice plugin, hand-copied to `driftsys/metapowers`, is
  replaced by the plugin that `pack` generates from the bundle `upskill`.

## Consequences

- `upskill update` removes the items of a recorded bundle that is no longer in
  the source (here `prompt-engineering`) as "no longer in source" and drops the
  bundle record (issue #649). For an install by item name, `update` removes the
  old `upskill-cli` as "no longer in source" and keeps the other six old skills
  beside the plugin's copies. A user with the old install must run
  `upskill remove` on the seven old names.
- Publishing to `driftsys/metapowers` is a manual step of each release. A
  release can ship before the plugin is regenerated.
- A tag exists a few minutes before its release binaries finish uploading, so
  `install.sh` can install the previous version in that window.
- Every user gets the `install.sh` line for a newer release, also when the CLI
  came from `cargo install` or a package manager.
- opencode users running `upskill add driftsys/upskill` see the line that
  reports one skipped hook item.

## Alternatives considered

- **Release check in the hook script with `curl` on the GitHub API.** Rejected:
  version logic in shell, a dependency on `curl`, two copies, and no shared
  cache.
- **A release check plus `upskill self-update`.** Rejected for now: it needs
  binary replacement, checksum and atomic-rename code, and a second install path
  beside `install.sh`.
- **Install-method detection for the release line.** Rejected: it adds code for
  a message that is correct for most users.
- **A shared time budget for the content lookups and the release check.**
  Rejected: a slow network could prevent the release check every day.
- **An alias for the old skill and bundle names.** Rejected: upskill is before
  1.0.
