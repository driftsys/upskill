# Generation and installation

This record describes the existing module boundaries. It does not extend
implemented client support. See [ADR-0001](../adr/0001-multi-kind-compiler-architecture.md)
and [ADR-0003](../adr/0003-generation-pipeline.md) for the architecture decisions.

The Rust crate provides both a library and CLI. `src/main.rs` and `src/cli.rs`
provide the CLI surface and orchestration. Domain work belongs in library
modules; presentation stays at the CLI boundary.

| Responsibility                              | Modules                                                |
| ------------------------------------------- | ------------------------------------------------------ |
| Content model and parsing                   | `src/model/`, `src/parse/`                             |
| Source classification and retrieval         | `src/source.rs`, `src/fetch.rs`                        |
| Bundle composition                          | `src/bundle.rs`                                        |
| Per-client rendering                        | `src/generate/`                                        |
| Installation and installed-state operations | `src/pipeline/`, `src/lockfile.rs`, `src/ancillary.rs` |
| Pure legacy-state interpretation            | `src/legacy/`                                          |
| Native integrations                         | `src/plugin.rs`, `src/mcp.rs`                          |
| Author commands                             | `src/lint.rs`, `src/fmt.rs`, `src/scaffold.rs`         |

The central flow is source content to parsed items to per-client output.
Bundles compose items and native integrations. Generated content is copied to
its target location; the lockfile records installed state. The
[portable format](../specification/format-spec.md) owns field and layout details;
this record does not duplicate those contracts.

Current content generators are Claude Code, Copilot and OpenCode. Generation
and MCP target sets differ, as recorded in
[ADR-0012](../adr/0012-consumer-client-filtering.md).
[ADR-0013](../adr/0013-agent-customization-targets.md) adds design commitments for
Codex, Cursor and Gemini CLI; it does not establish implemented adapters.

## Pure legacy-state projection

The public library boundary
[`legacy::project_legacy`](../../src/legacy/mod.rs) accepts a borrowed typed
`Lockfile` and returns an owned `LegacyProjection`. It has no scope-root input,
I/O, state writer or CLI dispatch. [AD-0015](../adr/0015-pure-legacy-state-projection.md)
records the choice of this intermediate boundary; the
[specification](../specification/specification.md#41-pure-legacy-state-projection)
owns its requirements.

### Snapshot and interpreted rows

The snapshot is an exact typed clone, including original vector order and every
current field. It does not preserve unknown JSON fields or serialization bytes.
Items and bundles retain their original index and cloned record. Plugins precede
MCP entries in a tagged integration vector; each integration index addresses its
original plugin or MCP vector. Native targets, scopes and statuses remain facts,
without runtime verification or permission to operate on the target.

Unsupported schema values retain all these records, produce a global diagnostic,
and return without interpreting sources, clients or destinations. For schema 1,
source decoding uses `parse_install_source_label`; parse errors retain the raw
record and actionable parser message. Successful parsing does not verify source
availability, a revision or generated bytes.

Every item has `RequestedSelection::Unresolved`. Effective generation clients
cannot recover requested families lost through author audience filtering, and a
Copilot client does not distinguish CLI from VS Code Local. Integration targets
remain separate from requested content selection.

### Historical clients and layout

[`legacy::layout`](../../src/legacy/layout.rs) fixes the historical client set to
Claude, Copilot and OpenCode. An empty recorded list expands to those three in
that order. Explicit known clients retain first-occurrence order and produce one
candidate each; unknown spellings produce diagnostics and remain in the cloned
record. An unknown-only list produces no candidates.

The nine kind/client path mappings use the installed alias. Current
[`pipeline::output`](../../src/pipeline/output.rs) wrappers delegate to the same
native `PathBuf` helpers through explicit current-client conversion. Those
helpers retain raw-name behavior for existing pipeline callers. Only the
projector validates names before converting paths to forward-slash strings:
empty names, dot, dot-dot, slash, backslash, colon and control characters suppress
candidates; spaces and Unicode remain representable.

Each candidate carries a client, relative entrypoint and relative resource search
base. Skills and OpenCode rules are directory-backed; flat entrypoints use a
sibling name directory for resources. These paths are relative to a later
caller's established legacy scope root. They do not establish existence,
containment or ownership, enumerate resources or permit recursive adoption.
Malformed sources do not erase otherwise known layout facts. Bundles and
ancillary files have no candidates.

### Diagnostics and later consumers

Diagnostics are structured data located at a global, item or bundle position.
The projector continues across malformed rows. Separate borrowed-key groups
collect duplicate `(kind, name)` identities and identical entrypoint candidates
across distinct rows, retaining every affected index. Collision locations anchor
at the first affected row; no record wins or disappears. Disjoint client lists
can duplicate an identity without sharing an entrypoint. Resource-tree overlap
analysis requires later verified resource enumeration.

The projection has no serialization contract, ownership record, artifact hash,
mode, source-verification result or generic operation-blocking flag. Later
planners determine which unresolved facts an operation requires. Source
verification, historical rendering, resource enumeration, adoption, requested
selection reconciliation, schema-2 lifecycle preservation, exact backup and
transactional execution remain outside this boundary.

[`tests/legacy_projection.rs`](../../tests/legacy_projection.rs) pins typed
preservation, all nine literal layouts, client order and candidate identity,
source compatibility, malformed and duplicate rows, unsupported schemas and
root-independent paths. Existing pipeline output and resource tests cover the
unchanged wrappers. These checks do not establish native Windows execution,
native discovery or actual artifact ownership.
