# Rust 1.85 compatibility repair plan

> For agentic workers: use superpowers:subagent-driven-development, then Codex PR review before merge.

Goal: make the existing declared Rust 1.85 minimum real and prevent stable-toolchain refactors from silently raising it.

Evidence: `cargo +1.85.0 check --locked --lib` on ownership head 90a7dd7 fails with 19 E0658 let-chain errors in nine files unchanged from main ab6795c. The binary contains further let chains. `/private/tmp/upskill-ownership-msrv.log` records the initial RED. No ownership change introduced these failures.

Decision: preserve Rust 1.85 rather than raise the minimum. This follows AGENTS.md and the foundation's global constraints. Repair this prerequisite in a separate PR before legacy migration. Existing runtime behavior and source formats stay the same.

## Global constraints

- Rust edition 2024, minimum Rust 1.85; add no dependencies.
- Only main.rs writes to stdout/stderr; preserve current I/O, errors, and short-circuit evaluation.
- Do not change user behavior, generated bytes, ownership/state schemas, source syntax, or target selection.
- Use the existing action revisions and CI style. Do not mutate repository rules or required-check settings.
- Work only in the assigned worktree; preserve unrelated branches and edits.

## Task 1: Restore and continuously check the declared minimum

Files: Cargo.toml; src/generate/claude.rs; src/generate/link_rewrite.rs; src/lint.rs; src/pipeline/mod.rs; src/pipeline/discovery.rs; src/pipeline/install.rs; src/pipeline/lifecycle.rs; src/scaffold.rs; src/search.rs; src/main.rs; .github/workflows/ci.yml; this plan. Inspect tests/examples only if the Rust 1.85 all-targets command reports another concrete incompatible construct; report any extra file before editing.

Acceptance criteria:

1. Record the current compiler-error RED before changes using installed Rust 1.85.0. `cargo +1.85.0 check --locked --all-targets` must eventually exit 0. Compiler diagnostics are the acceptance failure for this compiler compatibility task; do not add a test merely mirroring syntax.
2. Add `rust-version = "1.85"` to package metadata. This makes Cargo and Clippy consume the declared minimum rather than relying solely on prose.
3. Replace post-1.85 let-chain syntax with equivalent stable constructs. Preserve order and laziness, especially recursion, filesystem operations, error propagation, path lookup and percent-decoding bounds. Do not turn lazy conditional work into unconditional tuple evaluation. Avoid lint suppressions where normal structure suffices.
4. Use existing unit and CLI regression tests to pin behavior; add a focused semantic test only if an existing branch being rewritten has no meaningful protection. Run focused suites covering the changed generators, lint, discovery, dependency conflicts, lifecycle and scaffold paths.
5. Add an Ubuntu CI job named `MSRV (Rust 1.85)` that installs exactly Rust 1.85.0 and runs `cargo check --locked --all-targets`. Reuse checkout/toolchain/cache actions already used in this workflow. Add the job to the aggregate `CI` dependencies so a failure fails the required gate. Keep existing stable Windows/Linux tests and stable Clippy intact.
6. Run `just fmt`, `just verify`, and the exact Rust 1.85 all-targets gate on final code. Verify package metadata reports rust_version 1.85 and inspect the workflow's aggregate dependency. Commit with Conventional Commits.
7. Report all edits, RED/GREEN command results, final gate logs and exact head. Do not claim Rust 1.85 tests were executed if only type-checking was done; stable existing test suites remain the runtime evidence.

Review focus: short-circuit semantics and borrow lifetimes in rewritten conditions; no generic refactor; declared minimum matches CI; the CI job participates in the required aggregate; no dependency/lockfile drift.
