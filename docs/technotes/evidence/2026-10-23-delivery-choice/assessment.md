## What remains uncertain and how it affects the recommendation

- Shared installed skills are possible; they do not establish a general shared
  rule or agent format. Exact native route and required restrictions remain
  adapter responsibilities.
- There is no controlled storage-layout comparison for latency or provider cache
  accounting. The recommendation makes no performance superiority claim.
- Native rule applicability, compatibility readers, user/Linux/IDE coverage,
  simultaneous sessions, full source exclusions and native-effect recovery
  remain production gates. These limits do not prevent proposing a design that
  rejects unsupported mappings.
- The current OpenCode request path is blocked. Its older successful controls
  show feasibility under their frozen context; neither those successes nor
  current catalog evidence qualify the new client release.
- The self-contained default reduces mandatory runtime dependency and
  cross-client selection coordination. It still requires package-completeness,
  active-reader retirement and native registration lifecycle checks.

The [proposal](../../../wip/specs/2026-10-23-customization-delivery-proposal.md)
has since been revised for Fable review around managed client packages and a
rules/skills/subagents MVP. These retained observations do not qualify the newly
proposed Copilot plugin rule component or package-owned subagent registration.
The revised proposal preserves uncertainties as explicit qualification work. It
is not a support announcement.
